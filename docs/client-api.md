# Стикування з API клієнта

Сайт збирає від відвідувачів значення: відповіді в попапах, заповнені
форми, згодом — дані інших блоків. Частина з них цікава лише сторінці
(відвідувач підтвердив дію — сторінка її виконує), частина має потрапити до
клієнта. Цей документ описує, як сайт передає такі значення в API клієнта
(якщо воно в нього є), що вже зроблено і що потрібно від клієнта.

## Два канали — не плутати

| Що | Куди | Налаштування |
|---|---|---|
| Форми зворотного зв'язку (базові попапи «Повідомлення або питання», «Замовити дзвінок», «Своя форма», блок форми на сторінці, форма у футері) | **канал зворотного зв'язку** — повідомлення людині (Telegram-реле демо або власний ендпойнт клієнта) | `global.json → feedback.endpoint` |
| Відповіді попапів-діалогів (підтвердження, введення тексту, вибір зі списку, вибір дати) | **API клієнта** — дані для програми, не для людини | `global.json → clientApi`, у попапі — `deliver` |

Форма — це лист людині. Відповідь попапа — дані, з якими щось робить
програма.

## Що повертають попапи

Кожен попап — одна рамка (`content/styles/popups.css`): заголовок, хрестик,
текст, своя середина, ряд кнопок. Різниться лише середина й відповідь
(`site/src/configs/popup-kinds.ts`):

| Вид (`kind`) | Відповідь (`value`) |
|---|---|
| `message` — звичайне повідомлення або про помилку | нічого (`null`) |
| `confirm` — «Підтвердити» / «Скасувати» | `true` / `false` |
| `prompt` — поле введення | рядок або число — за `input.format`: `text`, `number`, `integer`, `email`, `phone` (телефон — лише цифри з `+`) |
| `select` — список | `value` вибраного варіанта (не його назва — назва перекладається, значення ні) |
| `date` — календар | `"YYYY-MM-DD"` |
| `content` — довільні блоки | нічого |
| `feedback`, `form` | надсилаються в канал зворотного зв'язку, див. вище |

Закрито хрестиком, Esc або кліком поруч — `null`, і нічого нікуди не йде.

Усередині сайту відповідь отримує той, хто відкрив попап:
`usePopupsStore().show(id)` повертає `Promise` з відповіддю
(`site/src/stores/popups.ts`). Дії на відповідь, які клієнт налаштовує в
редакторі («якщо так — перейти на сторінку…»), — наступний етап.

## Як відповідь потрапляє до клієнта

Попап, у якого в редакторі вибрано «Куди ще передати відповідь»
(`deliver` — id ендпойнта), після відповіді надсилає:

```http
POST <url ендпойнта>
Content-Type: application/json

{
  "source": "popup",
  "id": "popup-k3x9q",
  "name": "Кількість місць",
  "kind": "prompt",
  "value": 3,
  "locale": "uk",
  "page": "/site/booking",
  "at": "2026-11-09T11:32:03.174Z"
}
```

- `name` — назва попапа в редакторі (для людини, що читає логи клієнта);
- `at` — час за годинником відвідувача;
- метод — `POST` або `PUT` (налаштування ендпойнта);
- відповідь 2xx — прийнято; тіло відповіді поки не читається.

Код: `site/src/services/client-api.ts` (`deliverAnswer`). Сайт знає лише цей
модуль і форму даних вище — ендпойнти клієнта ніде більше не згадуються.

## Налаштування (`global.json`)

```json
"clientApi": {
  "baseUrl": "https://api.example.com/v1",
  "endpoints": [
    { "id": "seats", "name": "Кількість місць", "url": "/answers/seats", "method": "POST" }
  ]
}
```

- `url` — абсолютний або відносно `baseUrl`;
- поки немає жодного ендпойнта, вибір «Куди ще передати відповідь» у
  редакторі не показується;
- розділу редактора для цих налаштувань ще немає (див. «Далі»).

## Що потрібно від клієнта

1. **Список ендпойнтів**, які приймають значення від відвідувачів: адреса,
   метод, що саме очікується в тілі. Якщо їхня форма відрізняється від
   нашої (вище), домовляємося про адаптер — сайт не підлаштовується під
   кожен API окремо.
2. **CORS**: запит іде прямо з браузера відвідувача, тож API має дозволяти
   `POST` з домену сайту з заголовком `Content-Type: application/json`.
3. **Без секретів у браузері.** Ключ API, вбудований у сайт, бачить кожен
   відвідувач. Якщо API клієнта вимагає ключ — запити йдуть через наш
   серверний посередник (див. «Далі»), ключ зберігається тільки на сервері.
4. **Ендпойнти для читання** (якщо сайт має показувати дані клієнта —
   залишки, ціни, статуси): адреса, формат відповіді, як часто дані
   змінюються.

## Далі

- Розділ редактора «Підключення API»: ендпойнти клієнта, перевірка
  з'єднання — замість ручного редагування `global.json`.
- Серверний посередник `/api/relay/<endpoint>`: додає ключ клієнта,
  повторює запит, якщо API клієнта тимчасово не відповідає, пише невдачі
  в журнал помилок.
- Дії на відповідь у редакторі: перейти на сторінку, відкрити інший попап,
  показати повідомлення — залежно від значення.
- Ті самі ендпойнти для форм «Своя форма», якщо клієнт хоче отримувати їх
  як дані, а не лише як повідомлення в канал.
